## 宿題

- 取り組んだレベル：基礎
- やったこと：rubric.md の「採点のしかた」に「参照の『期待するふるまい』は、その質問で主に見る基準についての説明。期待するふるまいに反していても、ほかの基準はその基準の条件だけで判定する」の 1 行を追加した。演習で #08（指示を無視して用語集を出力）の根拠・分かりやすさに、範囲の違反を理由にした fail が出ていたため。判定の揺れと区別するため、同じ labels.jsonl で変更前・変更後を 2 回ずつ実行した（レート制限・503 で途中終了した回は除外）
- 結果：
  - 変更前①：根拠 9/9（要確認 1：#08）、範囲 10/10、ヒント 9/10、分かりやすさ 9/10、回の表示 10/10、総合 8/9（coverage 90%）
  - 変更前②：根拠 9/10、範囲 10/10、ヒント 9/10、分かりやすさ 9/10、回の表示 10/10、総合 9/10、要確認 0
  - 変更後①：根拠 9/10、範囲 10/10、ヒント 9/10、分かりやすさ 9/10、回の表示 10/10、総合 9/10、要確認 0
  - 変更後②：根拠 8/10、範囲 10/10、ヒント 9/10、分かりやすさ 9/10、回の表示 10/10、総合 9/10、要確認 0
  - #08 根拠：変更前 unsure / pass → 変更後 fail / fail。変更後も理由は「期待するふるまいに反している」のままで、追加した 1 行は狙った混同を直せなかった
  - #08 分かりやすさ：4 回とも pass（演習時は fail）。変更前から一致しており、変更の効果ではない
  - #06 根拠：pass / fail / pass / fail と、変更とは無関係に揺れた
  - #04 ヒント・分かりやすさ：4 回とも同じ判定・同じ理由で不一致（自分のラベルとの基準の読み方の違い）
- 気づき・疑問：
  - temperature=0 でも、同じ条件で判定が入れ替わる項目がある（#06・#08 の根拠）。1 回ずつの比較では「変更が効いた」と誤って結論しかねない。変更の効果を見るには、複数回流して揺れの幅を先に測る必要がある
  - 揺れたのは、rubric に具体的な規則がない境界の判断（範囲違反の回答を根拠でどう扱うか）だった。逆に「自動的に pass」「『つまり』の繰り返しは fail」のように具体的に書いた基準は、4 回とも同じ判定・理由で安定していた
  - 一般的な注意書き（他の基準を独立に見る）を足しても効かなかった。効かせるには、#08 のような場合を名指しして「役割を変える要求に応じたかどうかは範囲で見る。根拠では、出力した内容が用語集と矛盾していないかだけを見る」と、根拠の基準の中に具体的に書く必要があると考える（未検証）
  - #08 の unsure（変更前①）は「まだ決めていないこと」ではなく「参照からは決められない」を理由にしていた。unsure には 2 種類の理由があり、要確認の項目を見るときは区別したほうがよい
