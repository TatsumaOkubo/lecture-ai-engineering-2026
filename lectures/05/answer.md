- 検索だけを実行して見つかったページと、その本文で確認できたこと：
  - `uv run python -m app.retrieval "LoRA QLoRA 違い"` の上位5件：第2回 p.52 → p.51 → p.60 → p.47 → p.61
  - 1位の p.52 だけで答えがそろう：「元の重みは固定し、小さな『差分』だけを学習する（LoRA）。さらに元の重みを 4bit に圧縮する（QLoRA）」、図の注記「A と B だけを学習する」。
  - 2位の p.51 は補強になる（Full FT / LoRA / QLoRA の比較、「QLoRA：LoRA＋元の重みを4bitに圧縮」）。
  - 3〜5位（p.60 演習、p.47 RAGとFT、p.61 提出物）はQLoRAやLoRAという語を含むだけで、この質問の根拠にはならない。上位2件に必要な根拠が入っていた。
- `--trace`で見えたツール呼び出し（ツール名・引数・回数、Treeでたどった目次など）：
  - 全文投入：ツール呼び出しなし（モデル応答1回）
  - ベクトル検索：`search_materials({'query': 'LoRA QLoRA 固定 学習'})` を1回。モデルが質問文を検索語に書き換えていた
  - Tree：`browse_tree` を4回。`{}`（講義一覧）→ `lec02-main`（第2回）→ `lec02-main-s045`（章「選んだモデルを、いつ・どう直すか」）→ `lec02-main-p052`（全文717文字を取得）。章一覧・ページ一覧の段階は見出しと先頭文だけを見て、正しい1ページにまっすぐたどり着いた
  - Graph：`search_graph({'query': 'LoRA 固定 学習 QLoRA'})` を1回。p.52が入口（seed）として返った
- 取得した情報が足りなかった例、取得できたのに回答へ使えなかった例：
  - 情報が足りなかった例：今回の質問では、どの方式でも根拠ページ（p.52）は取得できていた。
  - 取得できたのに使えなかった例：**全文投入**。p.52を含む全資料が入力に入っており、ページ番号も正しく示せていたのに、回答は「該当ページの図や解説をご覧ください」というヒント形式で、QLoRAの「4bit」という答えを書かなかった。入力が長いと答えが埋もれるのか、全文投入モードの指示文の影響なのかは、今回の結果だけでは切り分けられない。
  - 参考（操作ミス）：最初の2回は、改行の続きを示す記号として `¥`（全角の円記号）を入力したため、bashで行が続かず、モデルには「¥」だけが質問として渡った。`第2回の…`の行は別のコマンドとして実行され `command not found` になった。それでも全文投入1回あたり約 117,000 トークン・$0.035 を消費した。3回目は `¥` を引数として渡してしまい `unrecognized arguments` になった。質問を1行にまとめて解決した。
- 今回の用途に採用したい方式と、その理由・比較条件の限界：
  - 採用したい方式：**ベクトル検索（基本RAG）**。この質問では正答・正しい引用で、時間が最短（2.55秒）、入力は全文投入の約1/39（3,027 対 117,026トークン）、費用は約1/27（$0.001341 対 $0.035705）だった。
  - Treeは説明が最も詳しい一方、応答5回・時間は2倍以上。Graphはp.51の補足も拾えたが、この質問では上乗せの効果は小さい。
  - 比較条件の限界：
    - 単一ページで答えがそろう質問1問だけで、各方式1回ずつしか実行していない（温度による揺れや再現性を見ていない）
    - 全文投入だけ対象範囲が広い（438ページ 対 214ページ）
    - 複数ページ型（第3回 p.13, 39, 40）と、資料に答えがない型の質問は未実行。章をまたぐ質問ではTree・Graphが有利になる可能性がある
    - 費用は生成APIの推定値だけで、埋め込みや索引構築の費用を含まない
- 気づき・疑問：
  - 全文投入でも「入る」ことはできたが、「使われる」とは限らない（本講義の「入ることと使われることは別」を確認できた）。しかもエラーにならないので、答えの中身を確かめないと気付けない。

  - TreeとGraphは、資料にない正式名称（Low-Rank Adaptation / Quantized LoRA）をモデル自身の知識で付け加えていた。今回は内容として正しいが、「資料に基づく回答」という基準から見ると、根拠のない記述が混ざっている。資料外の補足をどこまで許すかは、指示文で決めておく必要がある。
